### How the pieces work

- **Memory**: detections become tracks in 4K source pixels, moved by their own estimated drift (~62–68 px/frame downwards in both scenes) and reported while the camera looks elsewhere. It doubles mAP (0.31 -> 0.61 with the sweep), because every frame is scored against the whole 4K frame.
- **Hybrid camera**: scores reachable views by time since last full view, stale grid cells, and uncertain/never-zoomed objects. Uses Level 0 about 1/3 of the time.
- **Camera lag (important)**: the live service applies a camera command ~1 frame late, so a request can still show the old view. The server remembers its pending command and only sends moves legal from both positions. Before this fix, validations had 9–12 refused moves; now 0. The local evaluator does NOT simulate this lag.
- **Sequence reset**: state resets when `frame_index == 0` or the frame number goes backwards (the local evaluator reuses one sequence id).

- The background imagery is 3D (roofs shift with parallax) — likely photorealistic 3D map tiles in a simulator ("GimbalCamera"). Google's tile terms don't allow ML training, so for our own backgrounds prefer open national orthophotos (DK/FI/SE/NO), ~0.2 m/px.
- Camera geometry estimate: 600 m altitude, ~0.21 m/px, ~68° horizontal FOV, nadir.

## Running a server for a validation

```bash
cd drone-flyby
DRONE_CAMERA=hybrid .venv/bin/python -m uvicorn api:app --app-dir src --host 0.0.0.0 --port 9056
cloudflared tunnel --no-autoupdate --url http://localhost:9056   # prints a https://*.trycloudflare.com URL
```

Submit `https://<tunnel>/predict` in the **drone** form (Verify first). Quick tunnels get a new URL on every restart. Juan's servers and tunnels stop when his session ends, so the URLs in earlier chats are dead.

Local checks: `python src/local_evaluator.py --url http://localhost:9056/predict` (add `--realtime` for the frame clock).
